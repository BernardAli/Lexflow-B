Keep the evidence. Move the work forward.

Welcome to Lex Flow A I, a working document workflow prototype. This presentation follows the version zero point eleven demonstration guide. We will receive synthetic documents, review their evidence, and approve structured data. Then we will send that data to a fictional notary workspace.

Start with a synthetic workspace.

Start the local Python launcher or the Docker demonstration. The default port is eight thousand; the current development demo uses eight thousand and one. Sign in with a seeded demonstration account. Use synthetic records throughout, and keep the guide nearby for exact actions.

Two documents. One visible conflict.

Choose Start guided demo to create a fresh property purchase matter. Open the buyer questionnaire and the fictional land register extract. One source names sheet eight hundred and twelve; the other names eight hundred and seventy two. Lex Flow exposes the disagreement instead of choosing silently.

Let a person make the decision.

Inspect both suggestions before making a decision. In this fictional example, the reviewer chooses sheet eight hundred and seventy two. Confirm the other required fields and record a note where useful. Approval stays blocked until required values are valid and every conflict is resolved.

Approved values. Clear destination keys.

Open Export approved data and inspect the destination mapping. Generate a structured JSON file or a spreadsheet friendly CSV file. The file contains reviewed values linked to the source matter. Reopening, new evidence, or changed mappings require renewed approval and supersede earlier outputs.

Preview first. Send deliberately.

In Integrations, select the approved matter and Notary Desk Demo over H T T P S. Run a dry run and inspect the mapped payload. Send the approved data and inspect its accepted receipt. The request crosses verified local T L S to a separate encrypted case store.

Continue in the destination.

Open the demo notary and select the received case. Case details shows the approved values received from Lex Flow. Change the preparation stage and save it in the receiving workspace. Delivery evidence shows the receipt, source approval, and received payload fingerprint.

Teach the label. Keep the judgement.

Workflow Studio lets an office teach a literal label for a field. Test the label on a temporary example before saving it. An administrator saves the rule with version history. Future matching intake receives a suggestion, while human review remains mandatory.

Show observations, not invented savings.

Pilot measurement compares an observed baseline with reported work sessions. Missing observations stay empty, and acceptance rates are separate for each destination. The synthetic text benchmark records one hundred percent precision and ninety seven point two percent recall. These results do not establish real office accuracy, O C R quality, or customer savings.

Protect access. Preserve decisions.

In Settings, open My account to set up an authenticator. Save the recovery codes privately; each can replace a second factor once. The hardened profile requires enrollment before opening case records. Security also shows session controls, configured file encryption, and workspace audit verification.

Prepare for an interrupted day.

Durable transfer intents retain the original key across an interrupted delivery. An idempotent receiver prevents a duplicate after it has already accepted the data. Backups verify their manifest, files, audit history, and encrypted records. Restore uses a new directory and revokes old sessions while preserving evidence and enrolled factors.

A complete story. A clear next step.

The demonstration connects source documents, a human decision, approved output, and a signed fictional handoff. The release passed one hundred and eleven backend tests and twenty one interface tests. Browser checks covered one hundred and forty one page and panel views. Next, select a supported vendor and validate the workflow in an actual customer pilot.

This is a presentation of the documented prototype, not a live screen recording or a production certification. Real vendor integration and deployment validation remain future milestones.
